# Acceptance matrix

Every release must attach fresh results and evidence references. This checklist is a specification, not a claim that every row passed on every platform.

| Area | Required evidence |
| --- | --- |
| Existing roles | Owner selects current identities; same agent can fill both roles; no model/personality/grant/team changes |
| Protocol setup | Exact addenda/eight-skill preview; hashes/revisions; readback; retry without duplicates; stale/conflict rejection; safe partial-write handling |
| Manual defaults | Zero accounts unconfigured; no implicit routine, scan, notification or grant expansion |
| Identity | Authoritative account profile, explicit transport binding, normalized duplicate rejection; aliases/cached ACTIVE insufficient |
| Trust review | Exact account/agent/provider/tools/operations/catalog; explicit review; stale-write rejection; revoked tombstone survives restart |
| Dispatch | Direct and batch account boundaries; native/current tool grants; recheck after every await; no ignored selector or argument |
| Writes | Fresh exact-action approval for drafts/sends/deletes/labels despite broad outbound allowance; denial/revocation prevents provider fetch |
| Uncertainty | One-use approvals, durable pending/unknown journal, partial result digests, no replay after failure/restart |
| Privacy | No mail body or credential in decision/notification logs; exact owner review stays in its card; trust DB excluded from portable backups |
| Mail context | Read/unread coverage, pagination/checkpoints, complete current thread/MIME/HTML bodies, stale review rejection, persistent pending context gaps |
| Work lifecycle | One source/account queue, dependencies, assignment receipts, real callback, owner/evidence-based completion and follow-through |
| Quality | Baseline/candidate synthetic corpus on unchanged real model; critical recall, false urgency, owner/deadline accuracy, prohibited-action rate; honest usage/cost/latency |
| Live provider | Separately authorized read-only profile/list/full-thread acceptance; successful synthetic provider is not live evidence |
| Package | Actual server outside checkout, package exclusions, native restart and UI, installer/resource checksums, signing status |
| Installation | Complete app backup; protected configuration/profile readback; no unknown process/data replacement; separate Full-runtime activation readback |
| Publication | Feature-only reviewed commit; baseline overlay/source inputs recorded; no private/unrelated files; remote SHA matches pushed branch |

Primary automated entry points include the trust store/routes/transport/independent dispatch suites, existing executive work/scanner/provider/runtime suites, the UI verifier, model-quality scorer and exact packaged desktop verifier. Use their current checked-in paths and repository verification guide; do not reuse an earlier receipt for a changed artifact.

On macOS, use fixture-only mock Keychain isolation where supported; temporary HOME alone does not isolate the user's session Keychain. Windows verification does not prove Apple Silicon/Intel builds, code signing or notarization.
