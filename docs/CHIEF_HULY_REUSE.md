# Huly feature reuse review for C.H.I.E.F.

Reviewed 2026-10-07. This began as a bounded meeting/presence review. The owner's later live walkthrough explicitly broadened the reuse scope; the updated recommendation below supersedes the earlier transcription-first recommendation. No Huly source was copied into the current office implementation.

## Result

Keep Chief's actual OpenMausBot agent foundation, React host, private agent conversations and Team map. Reuse the recognizable Platform collaboration experience as a coherent subsystem: Contacts first, followed by configurable Cards/Spaces/Types, human Chat/Threads, Tracker, editable Documents, Office, persistent day calendar and Team planner, plus Inbox. The right companion panel must independently close or show Calendar/Office alongside main work. HR and Processes are deferred as product sections, although some selected source packages reference them internally.

For this broader scope, retaining Platform's Svelte workbench and supporting collaboration services is the preferred architecture to evaluate. It preserves the source-defined table/filter/editor system and shared identity/document model. A faithful port onto Chief's existing services is a materially different, larger implementation, and should be chosen explicitly rather than silently replacing the requested modules with simpler approximations. Neither option has been implemented. Contacts dependency inspection and the module map provide the concrete decision boundary; no live Platform workspace or data has been imported.

The installed image is `platformcollective/front:s0.7.426`, digest `sha256:03c16b1ab7ab590f988d781cea345bb2ba06b7f792b819cdb0dd0b39bf14bebe`. Its matching annotated source tag `s0.7.426` peels to commit `03b7aad7dc562f4f9769c51a4df08191a0393997`; use this release-matched source for integration preparation. The image has no OCI revision labels, so this is not cryptographic proof of the binary's source. The earlier develop pin below remains the historical reference for the initial meeting-only audit.

The original repository explicitly says it is frozen and its hosted service has closed; it directs development to [Platform-Collective/platform](https://github.com/hcengineering/platform/blob/develop/README.md). This review pins the successor's `develop` snapshot at [`bf00cde6765de1b66311d8c92e7e129261412877`](https://github.com/Platform-Collective/platform/tree/bf00cde6765de1b66311d8c92e7e129261412877). These are source inspection findings, not proof that its entire application has been deployed or tested here.

## Measured integration cost

Counts below are direct `@hcengineering/*` production dependencies at the pinned commit, not transitive totals:

- [`love-resources/package.json`](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/plugins/love-resources/package.json): 30 platform dependencies plus Svelte 4, LiveKit client, track processors and Krisp noise-filter integration. This UI is not a React component library.
- [`presence-resources/package.json`](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/plugins/presence-resources/package.json): 11 platform dependencies plus Svelte and `fast-equals`.
- [`services/love/package.json`](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/services/love/package.json): 20 platform dependencies plus Express, JWT helpers, WebSocket and LiveKit server SDK.
- [`love-agent/package.json`](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/services/ai-bot/love-agent/package.json): no direct `@hcengineering/*` runtime dependencies; uses LiveKit Agents/RTC Node, Deepgram SDK, dotenv and WebSocket. Runtime HTTP coupling to Huly still exists and must be replaced. Native RTC runtime support and transcription provider cost remain deployment considerations.

The successor's [architecture document](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/ARCHITECTURE_OVERVIEW.md) describes a distributed system with account, transactor, workspace, collaboration, storage and queue services. These costs initially argued against extracting only a few office features. With the owner's broader selection they become shared infrastructure for multiple requested modules and deserve evaluation as a retained subsystem. This is an engineering fit assessment, not a benchmark of Huly performance.

## Licensing boundary

The successor repository [LICENSE](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/LICENSE) and inspected invitation, presence, client and transcription source headers identify EPL-2.0. The transcription package also declares EPL-2.0. A package without a `license` field should not be assumed permissive; inspect its source and repository license together.

EPL code is not automatically Apache-2.0 merely because it is included in this Apache-based project. Any actual extraction should have a pinned provenance record, retained copyright/license notices, explicit modified-file tracking, and an identified source-availability/distribution path. The [official EPL-2.0 text](https://www.eclipse.org/legal/epl-2.0/) governs the obligations; obtain qualified review of a concrete derivative/distribution boundary before shipping copied modules. No entitlement bypass or restricted OpenMausBot enterprise implementation is involved in the current office.

The Huly meeting package also lists a Krisp integration. Its presence in an open-source manifest does not establish that all associated service capabilities can be used without separate terms or credentials. Chief does not import it.

## Behavior deliberately not inherited

- [`speakingWhileMuted.ts`](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/plugins/love-resources/src/speakingWhileMuted.ts) opens a dedicated microphone capture stream while the published microphone is muted. Even though it does not publish that stream, this conflicts with the current Chief expectation that off means no capture. Do not import it silently.
- Automatic join and device activation are unsuitable for the owner's explicit acceptance requirement.
- Huly's [meeting-minutes integration document](https://github.com/Platform-Collective/platform/blob/bf00cde6765de1b66311d8c92e7e129261412877/docs/livekit_meeting_minutes.md) includes unfinished access-control work. This note is not sufficient evidence of a current vulnerability, but it means authorization behavior must be tested against actual source rather than assumed from feature names.
- The owner's later walkthrough selects the recognizable personal-office/room arrangement and compact Office. Preserve that arrangement; game example records are not a request for game styling. Dragging a person into a room is a requested Chief enhancement: send an invitation for another person, retain acceptance and explicit media controls, and provide click/keyboard equivalents.

## Current implementation provenance and next boundary

`shared/office.ts`, `server/office.ts`, `server/office-media.ts`, `server/routes/office.ts`, `src/lib/office-client.ts`, `src/components/OfficePage.tsx` and `src/components/OfficeMedia.tsx` were implemented independently in the Chief clone. They use existing application infrastructure and installed LiveKit dependencies; no Huly files or assets were imported. Meeting notes are explicitly manual today, and private agent histories do not enter them.

Contacts source reuse is now the first selected integration slice. The quiet transcription worker remains a later candidate with explicit meeting capture consent/status, server-authorized listen-only identity, participant attribution, retention/deletion and participant-only access. Nothing here claims Contacts, the broader Platform subsystem or transcription has already been integrated into Chief.
